# Gateway

Go 기반 HTTP API Gateway입니다. 경로별 로드밸런싱, API 키 인증, 요청 제한에 더해 파일 기반 라우팅 갱신과 업스트림 장애 격리를 제공합니다.

## 실행

로컬 데모는 Go 1.25.6 이상에서 실행합니다.

```sh
go run ./cmd/server
curl -H 'X-API-Key: secret-key-123' http://127.0.0.1:8080/api/v1
curl http://127.0.0.1:9090/readyz
```

데모는 알려진 테스트 키를 사용하며 8081~8083번 포트의 업스트림을 전제로 합니다. 실제 업스트림 주소와 환경 변수 기반 키를 쓰려면 `examples/gateway.yaml`로 실행합니다. 먼저 `examples/routes.yaml`에 접근 가능한 업스트림 주소를 등록합니다.

```sh
export GATEWAY_SIGNING_KEY="$(openssl rand -hex 32)"
export GATEWAY_CLIENT_KEY="$(openssl rand -hex 24)"
go run ./cmd/server -config examples/gateway.yaml
```

다른 셸에서 요청할 때는 동일한 `GATEWAY_CLIENT_KEY` 값을 사용합니다. 공개 트래픽은 TLS를 종료하는 프록시를 통해 연결하고, 게이트웨이에 직접 접근할 수 있는 네트워크를 제한합니다.

## 라우팅과 복구

- 경로 세그먼트를 기준으로 가장 긴 prefix를 선택합니다. 경로와 쿼리는 업스트림에 전달됩니다.
- `route_file`은 게이트웨이 설정 파일의 경로를 기준으로 찾습니다. 저장할 때 임시 파일을 작성한 뒤 이름을 바꾸면 쓰는 중간 상태를 노출하지 않습니다.
- 스냅샷의 모든 라우트가 유효하면 한 번에 교체합니다. 잘못된 새 설정이 들어오면 직전 정상 테이블로 계속 요청을 처리합니다. 명시적인 `routes: []`는 라우트를 비웁니다.
- 파일 라우트의 응답 헤더 타임아웃 기본값은 5초입니다. 파일 모드에서는 업스트림에 직접 연결합니다.
- 서킷 브레이커가 설정되면 연결 오류와 업스트림 5xx를 실패로 집계합니다. 임계치에 도달한 업스트림을 피하고, 대기 시간이 지나면 요청 하나로 회복을 확인합니다. 이미 전달한 요청은 재전송하지 않습니다. 파일을 갱신할 때 설정이 같은 라우트는 서킷 상태를 유지하고, 변경된 라우트는 새 상태로 시작합니다.

## 인증과 운영

- 파일 예제는 API 키와 HS256 서명 키를 환경 변수에서 읽습니다. 업스트림은 `gateway` 발급자의 서명, 만료, 사용자 및 역할을 검증합니다. 클라이언트 키는 내부 토큰으로 교체됩니다.
- 직접 접속한 클라이언트가 보내는 전달 IP 헤더는 무시합니다. 신뢰하는 프록시만 `server.trusted_proxies`에 등록하고 프록시가 연결 주소를 전달 체인에 추가하고 `X-Forwarded-Proto`를 실제 외부 연결 스킴으로 덮어쓰도록 설정합니다.
- 속도 제한은 게이트웨이 프로세스별 IP 버킷을 사용합니다. 각 샤드의 클라이언트 수에는 상한이 있습니다.
- 관리자 주소는 루프백에서만 열립니다. `/livez`는 프로세스 상태, `/readyz`는 라우팅 테이블과 종료 상태, `/metrics`는 요청 수와 처리 시간 및 처리 중인 요청을 제공합니다. 준비 상태는 업스트림에 대한 별도 능동 프로브를 실행하지 않습니다.
- 서킷 브레이커와 속도 제한 상태는 프로세스 안에 저장됩니다.

```sh
go test -race ./...
go vet ./...
```
